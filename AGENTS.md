# Verification commands

- Unit tests: `./mvnw test`
- Targeted mutation feedback: `./mvnw -Pmutation-testing test-compile pitest:mutationCoverage`

# Mutation testing: two layers

- Layer 1 uses framework-generated mutants from PITest. Layer 2 uses
  requirement-driven semantic mutants generated by the agent.
- Run normal verification first, then Layer 1 for configured changed code. Add
  Layer 2 only for changed high-risk behavior; do not combine the two result
  sets into one mutation score.

## Layer 1: framework-generated mutants (PITest)

- Run the normal tests first, then the mutation profile after changing service behavior, streaming tokenization, or their tests.
- Separate `NO_COVERAGE` execution modes from `SURVIVED` weak assertions. Prioritize externally visible Ollama compatibility, final-chunk selection, timing boundaries, and lossless stream assembly.
- A useful new test must pass on the original and fail on the mutant. Avoid coupling tests to log wording or private implementation solely to move the score.
- Keep the initial score advisory and reject new meaningful survivors in changed code; use broader trend runs outside the pull-request critical path.

## Layer 2: agent-generated semantic mutants

- After normal tests and PITest, generate one to three requirement-driven semantic mutants for changed stream assembly, multi-turn stage selection, timing policy, tool-call compatibility, or fallback behavior.
- Prefer plausible ordering, state-machine, protocol, and multi-line data-flow mistakes over operators PITest already covers. Record the violated contract and an observable difference for each patch.
- Apply candidates only in a disposable copy or worktree. Require compilation; compiler failures are invalid, not killed. Use focused tests and virtual time for temporal behavior.
- Review survivors for equivalence and requirement validity. Add a contract test only when it passes on the original and fails on the frozen mutant. Do not introduce real sleeps or implementation-detail assertions to game detection.
- Keep the challenge bounded and report killed, survived, invalid, and equivalent candidates separately.
